# 04 · 聊天

路由：`#/chat`（聊天框总览，同首页第二屏）、`#/chat/<聊天框id>`（对话，全屏，不显示底部导航）。
语音通话：`04-call-dialing.jpg`（呼叫中）、`04-call.jpg`（通话中）、`04-call-camera.jpg`（开摄像头 + 打字）、`04-call-mini.jpg`（收起后的绿色胶囊）、`04-call-incoming.jpg`（他打来）、`04-call-log.jpg`、`04-call-transcript.jpg`（通话记录和转写）。

**一个聊天框 = 他的一个窗口**（比如"日常""工作"）。可以随时新开一个。

## 对话里能出现的东西

| 类型 `type` | 谁发 | 样子 |
|---|---|---|
| `text` | 双方 | 她是彩色气泡（颜色在外观里选），他是玻璃气泡；同一人 2 分钟内连发只有最后一条带尾巴，尾巴是 iMessage 那种从下角弯出去的小钩 |
| `sticker` | 双方 | 表情包图片 |
| `image` | 双方 | 图片，点开看原图 |
| `file` | 双方 | 文件卡：图标、文件名、`TXT 文件 · 43 B`，点了下载 |
| `alarm` | 他 | 闹钟卡：表盘指针按时间画，带"等待中 / 已响过 / 已取消" |
| `thinking` | 他 | 一行小字「思考过程 ›」，点开从底部弹出全文 |
| `call` | 双方 | 通话卡：`语音通话 12 分 04 秒 · 他打来的 · 看转写`，未接显示红色；点开跳到这通电话的转写 |
| `tool` | 他 | **命令行**：模仿 Claude 客户端，一行 `工具名(参数)`、一行 `⎿ 摘要`；绿点完成、橙点闪烁运行中、红点失败；点一行在原地展开完整输出 |

另外：

- 隔 10 分钟以上自动插一条时间分隔（今天 22:18 / 昨天 / 10月3日）
- 她最后一条消息下面显示：发送中… / 已送达 / `22:20 已读` / 发送失败 · 点一下重发
- 他正在输入时，底部显示跳动的三个点，顶部名字下面显示"正在输入…"
- **长按任意消息**弹出表态条：喜欢、赞、哈哈、!!、?（再点一次取消）
- 右上角一个胶囊两个键：📞 语音通话（见下面「语音通话」）、🔍 搜索（只在这个聊天框里搜文字消息）
- 往上滑到顶自动加载更早的消息，位置不跳
- 输入栏：＋ 打开面板（表情包 / 图片 / 文件）；有字时右边变成蓝色发送键，没字时是 ✦（预留给语音消息，见文末）
- 电脑上回车发送、Shift+回车换行；手机键盘上回车就是换行，点发送键发

## 数据结构

### 聊天框 `Session`

```json
{
  "id": "s-daily",
  "title": "日常",
  "agent": { "name": "他", "avatar": "https://…/avatar.png" },
  "status": "online",
  "typing": false,
  "context": { "used": 98000, "limit": 200000 },
  "unread": 2,
  "last": { "from": "ai", "text": "来，字和文件一起发的……", "at": "2026-10-06T14:20:00Z" },
  "preview": [{ "from": "me", "text": "emm 再随便发个文件吧！" }, { "from": "ai", "text": "来，字和文件……" }]
}
```

| 字段 | 说明 |
|---|---|
| `status` | `online` 在线（绿点）/ `busy` 在忙（橙点闪）/ `offline` 离线（灰点） |
| `context` | 窗口上下文用量，卡片上显示"窗口 49%"。没有就不显示 |
| `last.text` | 列表里的最后一句。非文字消息给 `[表情]` `[文件] xxx.txt` 这样的描述 |
| `preview` | 最近两条**文字**消息，最近在聊的那张宽卡上显示 |

### 消息 `Message`

所有消息共有：

```json
{ "id": "m7", "from": "ai", "at": "2026-10-06T14:20:00Z", "type": "file", "reactions": [{ "emoji": "heart", "from": "me" }] }
```

| 字段 | 说明 |
|---|---|
| `from` | `me`（她）/ `ai`（他） |
| `at` | ISO 时间。前端按它排序 |
| `readAt` | 只在她的消息上：他读到的时间，有就显示"几点已读" |
| `reactions` | 表态：`emoji` 取 `heart` / `like` / `haha` / `wow` / `ask`，`from` 取 `me` / `ai` |
| `clientId` | 她发消息时前端生成，**后端原样带回**，前端靠它把"发送中"那条换成正式的 |

各类型的额外字段：

| `type` | 字段 |
|---|---|
| `text` | `text` |
| `sticker` | `url`，`label`（可选，读屏用） |
| `image` | `url`，`name` |
| `file` | `url`，`name`，`size`（字节），`mime` |
| `alarm` | `time`（`"22:22"`），`label`，`date`（可选，默认显示"今天"），`state`：`pending` / `rung` / `cancelled` |
| `thinking` | `text` |
| `call` | `callId`，`direction`：`in` 他打来 / `out` 她打的，`status`：`done` / `missed` / `declined`，`durationS`（秒），`video`（布尔） |
| `tool` | `name`（如 `Bash` `Read`），`arg`（参数一行），`summary`（摘要一行），`output`（完整输出），`status`：`running` / `done` / `error` |

**工具调用的状态更新**：同一个工具调用开始时推一条 `status: "running"`，结束时**用同一个 `id`** 再推一次 `status: "done"` 带上 `summary` 和 `output`。前端按 `id` 原地替换，不会多出一行。

## 接口契约

### 聊天框

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/chat/sessions` | `{ "available": true, "items": [Session] }`。前端每 10 秒刷新一次 |
| `POST` | `/api/chat/sessions` | 请求体 `{ "title": "睡前聊天" }`，返回新的 Session。你的后端在这里给他开一个新窗口 |

### 消息

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/chat/sessions/:id/messages?limit=50` | 最近 50 条，按时间正序：`{ "available": true, "items": [Message], "hasMore": true }` |
| `GET` | `…/messages?limit=50&before=<消息id>` | 更早的 50 条（往上翻） |
| `GET` | `…/messages?limit=50&after=<消息id>` | 之后的新消息（只在 SSE 不可用时轮询用，可同时返回 `typing`、`readUpToAt`） |
| `POST` | `/api/chat/sessions/:id/messages` | 发消息，见下 |
| `POST` | `/api/chat/messages/:id/reaction` | 请求体 `{ "emoji": "heart" }`，取消时 `{ "emoji": null }` |
| `POST` | `/api/chat/sessions/:id/read` | 请求体 `{ "upToId": "m8" }`：她已经看到他的这条（含）之前的消息 |

**发消息**：

- 文字：`{ "type": "text", "text": "…", "clientId": "c-…" }`
- 表情包：`{ "type": "sticker", "stickerId": "st3", "clientId": "c-…" }`
- 图片 / 文件：`multipart/form-data`，字段 `file`、`type`（`image` / `file`）、`clientId`

返回存好的 Message（带上 `clientId`）。之后他的回复走实时推送。

### 实时推送（SSE）

`GET /api/chat/sessions/:id/stream`，`Content-Type: text/event-stream`。三种事件：

```
event: message
data: { …Message… }            ← 新消息，或同 id 的更新（工具调用跑完）

event: typing
data: { "typing": true }        ← 他开始 / 停止输入

event: read
data: { "upToAt": "2026-10-06T14:20:00Z" }   ← 他读到了她这个时间点之前的消息
```

- 浏览器的 EventSource 不能带请求头，**令牌放在网址参数 `?token=`** 里，后端这个接口要能从 query 取令牌。
- 建议每 20 秒发一行注释 `: ping` 保活，防止代理断开。
- 连续失败 3 次前端会自动退回每 3 秒轮询 `?after=`，后端两种都支持最稳。

### 表情包

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/api/stickers` | `{ "items": [{ "id": "st0", "url": "https://…", "label": "怎？" }] }` |
| `POST` | `/api/stickers` | `multipart/form-data`，字段 `file`：她自己存一张新表情 |

## 从窗口抓数据（映射参考）

如果他的窗口是 Claude Code / Codex 跑在 tmux 或 App Server 里，后端可以这样转：

- **他说的话** → `text`；**扩展思考** → `thinking`（每轮回复前一条）
- **每个工具调用** → `tool`：`name` 用工具名，`arg` 取最关键的参数（Bash 取命令、Read 取路径、Edit 取文件名），`summary` 取输出第一行或"读了 N 行""无输出"，`output` 放完整输出（建议截到 4000 字以内）
- **他发文件 / 表情 / 闹钟**：这些通常是他调用你提供的工具产生的，工具执行时顺便写一条对应类型的消息
- **正在输入**：窗口开始生成时推 `typing: true`，一轮结束推 `false`
- **已读**：她的消息送进窗口时，就可以推 `read`
- **`context`**：窗口当前上下文 token 数 / 上限
